**Honest scope.** This is **Node plus the frontend's own modules**, not a browser. There is no
browser in this repository's test path and installing one was out of scope, so what is proven
is that the packets decode and that the React components render the published values to HTML —
not layout, not interaction, not the Web Audio graph. `results/auditory_frontend_trial008.html`
is the step-8 instance of the same construction.

**21 checks, 19 pass.** The two that fail are a check in the step-9 evidence writer, not a
packet defect: `the card renders the decision the session published for that moment` and
`the winning source is marked FOCUSED and the other is attenuated`. It renders the dashboard

but the dashboard reads the **gain** stream of the state it is handed, and that state's newest

about which frame the renderer sampled, and it is reported with its `exit_code: 1` in the

## `signal_quality` under the relaxed policy (plan §3.17 item 6)

With `check_channels=False` the monitor's `reasons()` is empty by construction, so
`signal_quality.quality` was constantly 1.0 and a dead electrode reported `artifact=false`. The
census is now carried across: `EEGWindow.bad_channels` → `AuditoryWindow.bad_channels` →
`SessionFrame.bad_channels` / `SessionSummary.bad_channel_census`, and `_verdict` judges
`artifact` from it. **No window is rejected for it** — rejecting would bring back the mid-run
halt the relaxed policy exists to avoid. `producer._quality` publishes `bad_channels` too, so
the UI can name the electrode.

Test: `BadChannelEvidenceTests` holds one synthetic electrode (`F3`) at a constant value and
requires that the window is named in the census, that `artifact` is true and `quality` 0.0 while
`reasons` stays empty, that the first flagged window ends at or after 0.5 s (the flatline
detector's own run-up), and that the run still scored its windows with no failure. A clean run
must flag nothing. Each of those goes red under the two mutations above.

On this demo run the census is empty (`{}`): KU Leuven's converted trials carry no dead
electrode, so the fix is exercised by the synthetic test rather than by this trial.

## What is not verified here

* **No browser.** V2 is Node + the vendored frontend's own modules; no screenshot exists and
  none is claimed.
* **No live participant and no ANT hardware.** The 20-channel live contract
  (`models/auditory_kuleuven_live20.npz`) is not exercised by this run; hardware is step 11.
* **No DAC block timing / drift ppm** — see V5.
* **Window length is not a flag.** The session reads `window_seconds` from the decoder
  contract and the only models are 5 s, so the calibration's better 30 s/60 s points need a
  model fitted at those lengths, which is not this step's deliverable.
* **The demo's own two failing frontend checks** — see V2; the record keeps the failure.
* Step 9's `|Δt|` evidence (`results/auditory_media_20260914-trial008.json`) and this run's are
  separate runs of the same trial at different margins; they are compared as before/after, not
  as repetitions of one measurement.
